## 8. Bugs found and fixed during live execution

Both surfaced only when running against the real DEM, not against the
static tests:

1. **Wrong unpacking of `rasterio.Affine.to_gdal()`** in
   `normalize_heightmap.py`. Rasterio returns `(c, a, b, f, d, e)` —
   not `(a, b, c, d, e, f)` — so the code was reading the origin X as
   pixel width and got `res_y_m = 0.0`. The bug propagated into the
   SDF, which would have refused to render. Fix: use `ds.res` which
   returns positive `(xres, yres)` directly.

2. **Missing `setup.cfg`** for the ament_python package. Without it,
   setuptools installs console-script entry points under `bin/`
   rather than `lib/<pkg>/`, so `ros2 run` could not find them. Fix:
   add the standard ament_python `setup.cfg`:

   ```
   [develop]
   script_dir=$base/lib/lunar_south_pole_gazebo
   [install]
   install_scripts=$base/lib/lunar_south_pole_gazebo
   ```

After both fixes, `ros2 run` and `ros2 launch` both work cleanly.
